## 一、项目风格定义

### 1.1 天机是什么
天机是一个**易经六爻占卜工具**，核心体验是：
- 用户长按按钮 → 六爻逐个揭示 → 生成卦象 → 展示解读
- 整个过程应该有**仪式感**和**神秘感**
- 它不是一个严肃的学术工具，也不是一个娱乐玩具
- 它应该让用户感到"正在与某种古老系统对话"

### 1.2 视觉定位
- **赛博朋克 HUD 仪表盘** — 科技感外壳包裹东方玄学内核
- 像是在一块精密的全息屏幕上操作古老的占卜仪式
- 关键词: **精密、冷峻、克制、有仪式感**

### 1.3 "天机的味道"是什么
如果要用一句话描述正确的感觉：
> "深夜实验室里，一台军事级终端上运行的神秘占卜程序"

**是这个味道的**:
- 暗色背景上浮现清晰的青色/金色光线
- 信息像数据面板一样精准排列
- 操作时有"系统响应"的感觉
- 卦象揭示时有光粒子效果，暗示能量释放

**不是这个味道的**:
- ❌ 水墨画/宣纸/毛笔字 — 太传统，与科技感冲突
- ❌ 五彩缤纷的霓虹灯 — 太花哨，像夜店而不是终端
- ❌ 极简白色界面 — 太冷淡，没有仪式感
- ❌ 游戏UI风格的圆角气泡 — 太可爱，不够严肃

## 二、核心视觉元素

### 2.1 切角多边形
这是天机的视觉基因，不可替换。
- 所有容器、卡片、按钮都用 45° 切角
- 暗示"精密切割"、"工业制造"
- 与圆角的区别: 圆角=友好亲切，切角=精密严肃

### 2.2 扫描线纹理
- 横向细线覆盖在面板上
- 暗示"这是一个显示屏/全息投影"
- 必须非常淡 (alpha ≈ 0.010)，能感知到但不干扰阅读

### 2.3 角标记
- 四角的 L 型装饰线
- 暗示"校准标记/瞄准框"
- 让面板看起来像是"被精确定位的"

### 2.4 发光边缘
- 边框外侧有一层低透明度的宽发光
- 暗示"能量/活跃状态"
- 活跃状态时更亮，空闲状态时更暗

### 2.5 顶部强调条
- 每个面板顶部有一条细亮线
- 暗示"数据正在加载/面板处于激活状态"

## 三、历史踩坑记录

### 3.1 图片资源时期 (v3-v4)
**问题**: 使用 AI 生成的 1024x1024 PNG 作为卦象和数字图片
**结果**: 
- 图片与容器比例不匹配，要么拉伸要么留白
- 图片在不同设备上清晰度不一致
- 资源管理复杂
**教训**: 不用图片，所有图形纯代码绘制

### 3.2 过度装饰时期 (v4-v5)
**问题**: 每个面板都有发光+扫描线+角标记+强调条+多层边框
**结果**: 界面像"圣诞树"，视觉噪音太大，用户不知道看哪里
**教训**: 装饰要分层级。焦点层装饰多，内容层装饰少，装饰层最少

### 3.3 面板嵌套时期 (v5)
**问题**: HudPanel 里套 HudPanel 里再套 HudPanel
**结果**: 界面碎片化，看起来像"一堆小格子"而不是"一个完整界面"
**教训**: 面板嵌套最多两层。用间距和亮度差来分组，而不是用更多边框

### 3.4 圆角违规事件 (v8)
**问题**: 大重写时为了解决渲染质量问题，改用了 RoundedRectangle
**结果**: 违背了已约定的设计规范
**原因**: 规范只存在于对话记录中，没有文件化；重写时注意力在功能上，忽视了视觉约定
**教训**: 规范必须文件化；每次改代码后必须跑 Checklist

### 3.5 字体渲染问题
**问题**: 用 Canvas + CoreLabel 手绘文字，渲染质量不如原生 Label
**结果**: 文字模糊，位置不精确
**教训**: 能用 Kivy 原生 Label 的地方就用 Label，只在特殊场景用 CoreLabel

### 3.6 编码腐化事件
**问题**: 通过 PowerShell 编辑文件时破坏了 UTF-8 编码
**结果**: 中文字符变成乱码（"爻"变成"爷"）
**教训**: 涉及中文字符串时使用 Unicode 转义序列 (\uXXXX)

## 四、设计决策指南

当遇到具体问题时，按以下原则做决策：

### 4.1 "要不要加装饰？"
判断标准:
1. 这个装饰去掉后，界面会变差吗？
2. 如果不会变差，就不要加
3. 如果会变差，加最轻量级的版本

### 4.2 "这个元素该多大/多亮？"
判断标准:
1. 它是焦点层、内容层还是装饰层？
2. 焦点层: 最大最亮 (H1/CYAN/GOLD)
3. 内容层: 中等 (Body/SOFT/WHITE)
4. 装饰层: 最小最暗 (Caption/DIM)

### 4.3 "该用什么颜色？"
决策树:
```
是阳爻相关？→ GOLD
是阴爻相关？→ CYAN
是操作/按钮？→ PINK
是正面结果？→ GREEN
是详细信息？→ PURP
是辅助说明？→ DIM
是正文内容？→ WHITE 或 SOFT
```

### 4.4 "首页还是结果页该放这个信息？"
判断标准:
1. 起卦前需要知道的 → 首页
2. 起卦后才有意义的 → 结果页
3. 两边都需要的 → 可能不需要（过度信息）

### 4.5 "要不要做成可交互的？"
判断标准:
1. 用户会想点它吗？
2. 点了之后有有意义的反馈吗？
3. 如果两个都不是，就做成静态展示

### 4.6 "文字应该多大？"
决策树:
```
是页面标题？→ sp(30) Bold
是区块标题？→ sp(20) Bold
是卡片/爻名？→ sp(15)
是正文内容？→ sp(14)-sp(15)
是英文辅助？→ sp(11)-sp(12)
```

## 五、阳爻与阴爻的视觉表达

这是天机项目最核心的视觉元素，必须统一：

### 阳爻 (━━━ 实线)
- 一条完整的横线
- 颜色: GOLD (#FFD633)
- 含义: 阳、刚、动、天
- 视觉感受: 温暖、有力、完整

### 阴爻 (━ ━ 断线)
- 中间断开的两段横线
- 颜色: CYAN (#00DEF2)
- 间隔: 线宽的 18%
- 含义: 阴、柔、静、地
- 视觉感受: 冷静、开放、有间隙

### 卡片状态中的表达
- idle: 不显示爻线，只有虚线占位
- pending: 显示呼吸闪烁的实线（不区分阴阳）
- yang/yin: 显示最终爻线，伴随粒子效果

## 六、用户体验节奏

天机的完整体验节奏应该是：

```
[静] 首页等待状态 — 冷静、安静、邀请用户操作
  ↓
[蓄] 长按充能 — 紧张感逐渐积累，进度条推进
  ↓
[动] 六爻逐个揭示 — 每一爻都是一个小高潮，粒子爆发
  ↓
[显] 结果页展示 — 信息清晰呈现，仪式感收束
  ↓
[读] 用户自主阅读 — 从概要到详细，渐进式披露
  ↓
[回] 重新起卦 — 循环回到起点
```

每个阶段的视觉强度:
```
静(20%) → 蓄(40%) → 动(100%) → 显(70%) → 读(50%) → 回(20%)
```

## 七、参考图分析 (2026-04-10)

### 7.1 来源
墨刀 AI 设计稿，共三张：启动页、感应页、结果页

### 7.2 启动页参考要素
- 顶部: 终端状态行 (NETWORK: VOID_LINK_ENABLED + 时间戳)
- 中央: 大字 logo 区 ("赛博卦象"，占据视觉中心40%面积)
- 中下: 系统启动日志式文案 ("> 正在载入周易协议...", "> 核心版本: HEXAGRAM_CORE_26.0")
- 底部: 大尺寸操作按钮 ("接入虚空起卦")
- 氛围: 像终端开机画面

### 7.3 感应页参考要素 (用户评价"最有仪式感")
- 顶部: 协议名 + STATUS 状态文字
- 上方: 二进制数据流矩阵 (大面积01文字墙)
- 中央核心: 发光圆环 + 中心显示当前感应卦名
- 圆环外: 虚线轨道环 (暗示扫描)
- 下方: 六个方块指示器 (6爻生成进度)
- 底部: 系统日志行 ([SYSTEM] 量子态初始化完毕...)
- 特点: 大量留白围绕中心圆环，仪式感极强

### 7.4 结果页参考要素
- 顶部: "ENCRYPTED_MESSAGE_RECEIVED" + 大号卦名
- 卦名下: HEXAGRAM_ID + DATA_STABILITY 信息行
- 中央: 完整六爻图 (带角标记边框)
- 下方分块:
  - 卦义解读 (标记为 "DECODED")
  - 运势评估 (百分比数值 + 增减方向)
  - 风险等级 (LOW/MED/HIGH)
  - AI建议 (赛博朋友的建议 / AI_ADVICE)
- 底部: 两个按钮 "断开链接" / "保存至存储块"

### 7.5 参考图的优点 (应吸收)
- 终端/协议感的文案风格，增强沉浸感
- 系统日志式的状态反馈
- 感应页大量留白 + 中心焦点的仪式感布局
- 结果页从概要到详细的信息分层
- 六爻进度指示器
- 二进制数据流矩阵的氛围装饰

### 7.6 参考图的不足 (应改进)
- 字体偏小，可读性不足
- 边框缺乏天机规范的切角+发光+角标记
- 色块面积太小，发光不够强
- 扫描线纹理缺失
- 整体赛博风格不够显著

### 7.7 融合策略
将参考图的"终端仪式感"融入天机已有的"切角HUD规范"：
- 文案风格: 采用终端/协议式措辞
- 布局: 感应页采用中心焦点式
- 装饰: 保留天机的切角+发光+扫描线+角标记
- 字号: 按天机规范放大
- 色块: 按天机规范加大面积和发光强度
